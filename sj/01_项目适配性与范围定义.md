# 项目适配性与范围定义

## 1. 结论

当前项目适合实现“手机端局域网文件管理面板”，但必须作为一套独立的局域网访问模块建设，不能把现有桌面端数据层直接暴露给手机端。

## 2. 为什么适合

当前项目已经具备以下基础：

- 前端是 `React + Vite`
- 桌面壳是 `Tauri 2`
- 本地能力在 `Rust` 侧实现
- 现有项目已经有文件扫描、文件夹层级、重命名、打开文件、预览相关能力

这些条件意味着：

- 不需要再引入服务器或云服务
- 不需要重新搭建桌面端壳
- 可以直接复用 Rust 侧本地文件访问能力
- 可以把手机端面板作为当前软件的一个附属局域网模块

## 3. 为什么不能直接复用现有桌面端数据接口

现有桌面端模型偏向“资产工作台”，而不是“受限工作目录局域网文件面板”。

桌面端当前模型存在以下问题：

- 含有绝对路径字段
- 包含桌面端专用的项目、资产、规则语义
- 当前预览和打开逻辑部分依赖桌面运行时能力
- 当前数据结构不是面向手机端目录浏览场景设计的

因此手机端需要：

- 一套新的 API
- 一套新的相对路径数据模型
- 一套独立的认证和会话机制
- 一套后端统一路径安全校验流程

## 4. 第一版目标

第一版只解决一个问题：

“电脑端运行软件后，在同一 Wi-Fi 下，手机可以通过浏览器访问电脑端暴露的局域网地址，对电脑端用户主动选择的工作目录进行轻量文件管理。”

第一版必须支持：

1. 浏览指定工作目录下的文件和子目录
2. 基于相对路径进入目录
3. 文件名搜索
4. 受支持类型的轻量预览
5. 上传到当前目录
6. 下载原文件
7. 重命名文件或文件夹
8. 访问连接码认证
9. 桌面端显示当前地址和当前连接设备

## 5. 第一版严格边界

第一版明确不做：

- 外网访问
- 账号系统
- 云同步
- 删除文件
- 移动文件
- 批量操作
- 在线编辑文件内容
- 自动执行上传文件
- 高级媒体预览系统
- 复杂权限体系

## 6. 工作目录边界

工作目录必须满足以下原则：

- 只能由电脑端用户主动选择
- 手机端只能看到这个工作目录的相对路径
- 手机端不能知道电脑绝对路径
- 后端必须保证所有文件操作都无法逃逸工作目录

## 7. 第一版认证边界

第一版推荐只做“一次性连接码”，不同时做密码系统。

原因：

- 需求是局域网轻量访问，不是长期远程系统
- 一次性连接码更易理解
- UI 更简单
- 安全边界更明确
- 可以减少设置页复杂度

## 8. 项目级判断

从工程实施角度看，这个功能属于“适中复杂度新增模块”，不是重做项目。主要工作量集中在：

- Rust 局域网 HTTP 服务
- 路径安全封装
- 手机端独立 UI
- 桌面端设置页入口
- 认证和会话管理

因此本项目适合实现，但必须先把边界收紧，再进入代码阶段。
