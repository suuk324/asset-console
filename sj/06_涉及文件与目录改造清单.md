# 涉及文件与目录改造清单

## 1. 改造原则

这次功能不应粗暴塞进现有桌面端工作区文件中。应新增独立模块，并在必要处做小范围接入。

## 2. 现有文件预计改动

### Rust 侧

- `src-tauri/src/lib.rs`
  - 注册新的 Tauri 命令
  - 管理局域网服务状态

- `src-tauri/src/library.rs`
  - 仅保留与现有桌面文件工作台强相关的逻辑
  - 可抽出通用文件能力供局域网模块复用

- `src-tauri/Cargo.toml`
  - 增加 HTTP 服务依赖
  - 增加 MIME、上传、多部分表单、Cookie 会话等依赖

### 前端桌面侧

- `src/pages/SettingsPage.tsx`
  - 新增局域网面板设置区
  - 展示服务状态、地址、连接码、设备列表

- `src/store/useAssetConsoleStore.ts`
  - 新增局域网服务状态
  - 新增启动/停止/刷新连接码等动作

- `src/types/domain.ts`
  - 新增局域网服务状态类型
  - 新增设备记录类型

- `vite.config.ts`
  - 视最终构建方案而定
  - 若手机端独立打包入口使用 Vite 多入口，则需改这里

## 5. 推荐静态资源组织方式

可选方案 A：

- 手机端前端作为同一个 Vite 项目中的独立入口构建
- 构建产物进入单独目录
- Rust HTTP 服务直接托管该目录

可选方案 B：

- 手机端页面为一组手写静态 HTML/CSS/JS

结论：

- 推荐方案 A
- 不推荐方案 B

原因：

- 当前项目已有 React 体系
- 页面状态较多
- 上传、搜索、预览、提示等交互用 React 更稳

- `LanPanelStatus`
- `LanAccessAddress`
- `LanDeviceRecord`
- `LanAuthMode`
- `LanServerControlState`

## 7. 桌面端状态管理建议新增动作

- `loadLanPanelStatus`
- `startLanPanelServer`
- `stopLanPanelServer`
- `regenerateLanPanelCode`
- `selectLanPanelWorkspace`

## 8. 不建议的文件组织方式

不建议：

- 把所有逻辑继续堆进 `library.rs`
- 把手机端页面塞进现有桌面端页面目录并共用重状态 store
- 让手机端直接使用桌面端 `desktopBridge.ts`

原因：

- 会导致职责混乱
- 会让绝对路径模型渗透到手机端
- 后续维护成本很高
