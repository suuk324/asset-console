# 安全设计与路径隔离方案

## 1. 安全目标

本模块第一版必须保证：

- 手机端无法获知电脑绝对路径
- 手机端无法访问工作目录之外的任何文件
- 前端限制失效时，后端依然安全
- 上传文件不会被自动执行
- 重命名和下载都不会突破工作目录边界

## 2. 第一安全原则

所有文件相关 API 必须统一调用 `safeResolvePath`，不得各自分散拼路径。

这条规则必须执行到底。

## 3. safeResolvePath 设计要求

函数输入：

- `workspaceRoot`
- `relativePath`

函数职责：

1. 拒绝空值异常场景之外的不合法路径
2. 拒绝绝对路径
3. 拒绝盘符路径
4. 拒绝 UNC 路径
5. 拒绝 `..`
6. 规范化分隔符
7. 拼接为目标路径
8. 解析规范化后的真实路径
9. 校验解析结果仍在工作目录内
10. 发现符号链接逃逸时拒绝

返回：

- 受控的绝对真实路径

## 4. 必须拦截的输入

- `../secret.txt`
- `..\\secret.txt`
- `/etc/passwd`
- `C:\\Windows\\system32`
- `\\\\server\\share`
- `folder/../../x`
- `folder\\..\\..\\x`

## 5. Windows 特别风险

本项目运行环境在 Windows，必须特别考虑：

- 驱动器盘符路径
- 保留文件名
- 反斜杠路径混用
- junction 或 reparse point 逃逸

因此不能只做字符串包含判断，必须做真实路径层面的最终校验。

## 6. 符号链接与目录联接风险

即使用户传入的是合法相对路径，也可能通过目录联接把路径引到工作目录外。

因此建议：

- 解析过程中对目标路径执行规范化
- 上传目录、下载目标、重命名目标都在最终真实路径层校验是否仍在工作目录内
- 如有必要，第一版可直接拒绝对符号链接目标进行操作

## 7. 绝对路径隐藏要求

任何对手机端的响应都不能包含：

- 工作目录绝对路径
- 文件绝对路径
- 父目录真实路径
- 磁盘盘符信息

对外只允许出现：

- 工作目录显示名
- 相对路径
- 文件名
- 元信息

## 8. 认证安全

第一版使用一次性连接码时，需满足：

- 连接码随机生成
- 连接码长度足够
- 支持过期
- 认证成功后使用会话 Cookie
- 认证失败返回统一错误，不泄露过多状态

建议：

- 6 到 8 位数字或字母数字组合
- 刷新连接码后旧码失效

## 9. 上传安全

上传必须满足：

- 文件大小限制 200MB
- 同名冲突拒绝
- 不自动覆盖
- 不自动执行
- 不自动解析脚本
- 不根据扩展名触发任何本地动作

上传后只做：

- 保存文件
- 刷新目录
- 返回结果

## 10. 重命名安全

重命名必须满足：

- `newName` 只能是名称，不是路径
- 不允许路径分隔符
- 不允许 `..`
- 不允许系统非法字符
- 不允许与现有同目录文件冲突

## 11. 文本预览安全

文本预览必须限制大小。

推荐规则：

- 2MB 以内直接返回内容
- 超过 2MB 返回提示，不直接加载

理由：

- 防止手机端卡死
- 防止内存峰值过高
- 防止大文本导致响应时间过长

## 12. PDF 与媒体策略

第一版不做复杂文件解析器。

策略如下：

- PDF：浏览器原生内联预览
- 视频：优先下载
- 音频：优先下载
- 其他不支持类型：统一提示

这样能显著降低解析漏洞和兼容性风险。

## 13. 日志与错误信息要求

日志可以记录绝对路径，但仅限桌面本地日志。

对手机端错误提示不应暴露：

- 真实磁盘位置
- 系统内部异常堆栈
- Rust 底层错误原文

手机端只需要看到：

- 操作失败原因
- 可理解的用户提示

## 14. 第一版安全底线

若以下任一项未完成，不应进入发布测试：

- `safeResolvePath` 完成并接入全部文件 API
- 上传冲突校验完成
- 重命名冲突校验完成
- 绝对路径未对外暴露
- 认证与会话生效
- 大文本预览限制生效
