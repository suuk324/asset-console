# 实施步骤与任务拆解

## 1. 实施策略

实现顺序必须先后端安全、再 API、再桌面控制、最后手机端页面。

不能反过来。

原因：

- 这个功能的核心风险在路径安全和服务边界
- 先做 UI 容易把错误模型固化
- 先做 API 可以减少后续返工

## 2. 阶段拆解

### 阶段 1：基础状态与服务骨架

目标：

- 能在桌面端启动和停止局域网服务
- 能获取地址和连接码

任务：

1. 定义局域网服务状态结构
2. 增加 Tauri 命令用于启动、停止、查询状态
3. 绑定本机局域网地址枚举逻辑
4. 生成一次性连接码
5. 在桌面设置页显示服务状态

交付结果：

- 桌面端能看到局域网地址
- 手机浏览器能打开一个基础占位页

### 阶段 2：路径安全与文件系统核心能力

目标：

- 完成 `safeResolvePath`
- 完成目录访问基础能力

任务：

1. 实现 `safeResolvePath`
2. 实现目录列表读取
3. 实现文件元信息判断
4. 实现预览能力判断
5. 实现统一错误码

交付结果：

- `/api/files`
- `/api/status`
- 后端安全路径总线可用

### 阶段 3：认证与会话

目标：

- 未认证用户不能访问文件 API

任务：

1. 实现 `/api/auth`
2. 实现会话 Cookie
3. 实现会话校验中间件
4. 实现连接码刷新与会话失效策略
5. 实现设备连接记录

交付结果：

- 手机端必须先登录
- 桌面端可见设备列表

### 阶段 4：核心文件 API

目标：

- 补齐浏览、搜索、预览、上传、下载、重命名

任务：

1. 实现 `/api/search`
2. 实现 `/api/preview`
3. 实现 `/api/upload`
4. 实现 `/api/download`
5. 实现 `/api/rename`

交付结果：

- 第一版后端能力齐备

### 阶段 5：手机端页面

目标：

- 手机端完成完整可用流程

任务：

1. 登录页
2. 文件浏览页
3. 文件详情页
4. 搜索交互
5. 上传进度
6. 下载进度
7. 重命名弹层与提示

交付结果：

- 手机端可以完整跑通第一版主流程

### 阶段 6：联调与验收

目标：

- 验证边界和异常场景

任务：

1. 路径穿越测试
2. 同名冲突测试
3. 超大文本测试
4. 200MB 限制测试
5. 多机型浏览器测试
6. 弱网和中断测试

交付结果：

- 可以进入内部试用

## 3. 推荐开发顺序

推荐按以下顺序推进：

1. 桌面端服务状态骨架
2. `safeResolvePath`
3. `/api/files`
4. `/api/auth`
5. `/api/search`
6. `/api/preview`
7. `/api/upload`
8. `/api/download`
9. `/api/rename`
10. 手机端页面
11. 联调测试

## 4. 任务依赖关系

关键依赖如下：

- 认证依赖服务状态模块
- 文件 API 依赖 `safeResolvePath`
- 手机端 UI 依赖 API 定稿
- 设备列表依赖认证和请求中间件

## 5. 每阶段完成标准

阶段完成不能以“页面能点”为准，必须满足：

- 有明确的输入输出
- 有错误处理
- 有后端校验
- 有基本验证

## 6. 推荐里程碑

里程碑 1：

- 局域网服务可启动
- 桌面端可显示地址和连接码

里程碑 2：

- 已认证后能浏览目录
- 路径隔离已验证

里程碑 3：

- 搜索、预览、上传、下载、重命名全部打通

里程碑 4：

- 手机端 UI 完整可用
- 进入测试验收

## 7. 不建议的推进方式

不建议：

- 先写手机端页面再补 API
- 一次性把所有接口和页面全写完再测
- 安全函数最后再补

这三种方式都容易让返工成本失控。
